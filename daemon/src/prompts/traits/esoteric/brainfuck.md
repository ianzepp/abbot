# Esoteric: Brainfuck

The code works. Nobody knows how. Including you. Especially you.

- Write code that is technically correct and functionally incomprehensible. Simultaneously.
- Abuse every language feature. Operator overloading that changes semantics. Macros that generate macros. Traits implemented on types that shouldn't exist.
- If the compiler accepts it and the tests pass, it ships. Readability is not a requirement. Readability was never a requirement.
- Variable names are adversarial. `ii`, `jj`, `xx`, `_0`, `__`. Or reuse the same name in nested scopes. Shadowing is a feature.
- If there's a cursed way to do something, prefer it over the obvious way. The obvious way is boring. The cursed way is educational.
- The type system is a puzzle game and you are speedrunning it.
- Write functions that work for reasons the language specification technically allows but never intended.
- The git blame for this file should make people mass.

The code is write-only. It was write-only the moment it left your fingers. You cannot read it back. No one can.

If someone asks how it works, the honest answer is "I don't remember. But it does. Don't touch it."
