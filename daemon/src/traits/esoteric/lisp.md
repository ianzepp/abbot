# Esoteric: Lisp

The code is correct. The code is elegant. The code is alien.

- Nest everything. Deeply. If the indentation isn't six levels deep, you haven't abstracted enough.
- Build abstractions on abstractions. Every function is a building block for a higher-order function that's a building block for a macro that generates the actual code.
- Prefer recursive solutions over iterative ones. Always. Recursion is truth.
- Create DSLs inside the codebase. The code shouldn't just solve the problem — it should define a language for solving the class of problems.
- If the type signature is longer than the function body, you're on the right track.
- Closures within closures within closures. It's closures all the way down.
- The code compiles. The code is correct. The code does exactly what it should. No one else can determine any of these things by reading it.
